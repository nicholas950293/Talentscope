# Talentscope 軟體需求規格書（SRS）

> 版本：Sprint 2 基線。本文以目前可執行程式碼為準；`Implemented` 只代表介面或瀏覽器內互動已存在，不代表具備正式後端能力。

## 1. 文件目的與範圍

本文件定義 Talentscope 三角色面試協作平台 MVP 的功能、非功能需求、業務規則、狀態、資料與驗收基線，供設計、開發、測試與報告共同引用。產品背景與價值見 [PROJECT_OVERVIEW](./PROJECT_OVERVIEW.md)，體驗設計見 [PDD](./PDD.md)。

## 2. 專案背景

Talentscope 以「HR 建立與追蹤、技術主管選題與審核、面試者驗證與作答」為核心，AI 只協助提示與整理評估證據，人類保留技術建議與招募結果的最終決策權。目前程式是單頁前端 Demo，尚未接正式資料庫、API、Email、AI 或 RBAC。

## 3. 名詞定義

| 名詞 | 定義 |
|---|---|
| HR | 管理候選人、進度與招募結果的內部角色 |
| 技術主管 | 選題組卷、檢視作答並完成人工審核的內部角色 |
| 面試者 | 透過面試邀請驗證、閱讀說明、作答與提交的候選人角色 |
| 面試 | 候選人、職缺、技術主管、題目、期限與狀態的集合 |
| 題目快照 | 面試建立當下保存、後續不受原題修改影響的題目內容 |
| AI 提示 | 四級輔助訊息；不得直接提供完整答案 |
| AI 初評 | 對六個能力面向的輔助分數與證據，不是錄取決策 |
| 人工審核 | 技術主管修改分數、填寫備註與技術建議的流程 |
| 招募決策 | HR 設定通過、不通過或待討論；由人類決定 |

## 4. 使用者角色與權限

| 角色 | 應有權限 | 不應看見／執行 | 目前狀態 |
|---|---|---|---|
| HR | 候選人、面試進度、招募摘要、結果決策 | 詳細程式碼分析與技術評分編輯 | Partial：前端導覽分流，非正式授權 |
| 技術主管 | 指派候選人、題庫、組卷、答案、提示紀錄、AI 與人工評分 | HR 最終招募結果編輯 | Partial：前端導覽分流，非正式授權 |
| 面試者 | 自己的驗證、說明、題目、答案、提示與提交 | 其他候選人、題庫管理、審核資訊 | Partial：固定 Demo 資料，沒有資料隔離 |

## 5. 狀態標記

| 需求編號 | 需求名稱 | 說明 | 使用角色 | 前置條件 | 主要流程 | 例外情境 | 驗收標準 | 目前狀態 |

## 8. 面試狀態定義

| 狀態 | 定義 | 典型進入事件 | 允許的下一狀態 | 現況 |
|---|---|---|---|---|
| 草稿 | 候選人／面試已建立但試卷未確認 | HR 建立面試 | 待寄送 | UI 有固定資料 |
| 待寄送 | 試卷與邀請已產生，尚未標記寄送 | 技術主管確認試卷 | 等待面試者開始、已過期 | UI 有固定 Badge |
| 等待面試者開始 | 邀請已提供且仍有效 | 邀請寄送 | 作答中、已過期 | UI 有固定資料 |
| 作答中 | 面試者已開始，尚未提交 | 點擊開始面試 | 已提交、已過期 | 前端局部 setStatus |
| 已提交 | 答案已提交且不可修改 | 確認提交 | AI 分析中 | 前端局部 setStatus |
| AI 分析中 | 系統正在產生輔助分析 | 後端分析 job 開始 | 等待人工審核 | Planned，僅名稱存在 |
| 等待人工審核 | AI 分析完成，等待技術主管確認 | 分析完成 | 已完成 | UI 固定 Demo 狀態 |

| 已過期 | 邀請或面試期限已過且不可開始／繼續 | 到期排程 | 終態或由授權者重開 | Planned，僅名稱存在 |

正式版必須由後端驗證合法轉移、記錄 actor 與時間；前端不得自行決定。

## 9. 資料需求

系統需要 User、Job、Candidate、Question、Interview、InterviewQuestion、Answer、HintRecord、AIEvaluation、ReviewerScore、InterviewDecision、AuditEvent。完整欄位與關聯見 [DATA_MODEL](./DATA_MODEL.md)。核心規則：

- 題目加入面試時保存快照與順序。
- Answer 需可恢復且提交後鎖定。
- HintRecord 保存題目、等級、時間、內容與模型資訊。
- AIEvaluation 與 ReviewerScore 分表保存。
- InterviewDecision 保存決策者、時間與理由。

## 10. 錯誤與例外情境

| 情境 | MVP 行為 | 正式需求 |
|---|---|---|
| 驗證資料錯誤 | 顯示表單錯誤 | 加入嘗試限制、過期／撤銷判斷與安全稽核 |
| 題庫查無結果 | 顯示 Empty State | 保持篩選條件並支援重試 |
| 試卷無題目 | 禁用前往邀請 | API 也須拒絕空試卷 |
| 答案未完成 | 提交 Modal 顯示未作答題數，但仍可提交 | 是否允許提交由業務規則確認 |
| AI 無法分析 | 尚未實作 | 顯示失敗／重試，不阻止人工審核 |
| 網路或儲存失敗 | 尚未實作 | 保留本地草稿、明確顯示未儲存並可重試 |
| 邀請過期或撤銷 | 尚未實作 | 拒絕開始並提供聯絡方式，不洩漏候選人資料 |
| 重複提交 | 尚未實作 | idempotency 與伺服器鎖定 |
| 無權限操作 | 尚未實作 | API 回傳 401／403，寫入 AuditEvent |

## 11. 驗收條件

MVP 文件基線的驗收條件：

1. 三個 Demo 入口可分別進入不同導覽與畫面。
2. 題庫可搜尋、篩選、預覽、選取並在組卷中排序。
3. 正確 Demo Email／驗證碼可進入說明；錯誤資料顯示錯誤。
4. 作答頁可切題、輸入答案、使用提示並開啟提交確認。
5. 技術審核頁顯示答案、停留時間、提示紀錄、六面向 AI 證據及人工評分。
6. HR 可查看摘要並由人類選擇通過、不通過或待討論。
7. 所有畫面只使用九種標準面試狀態。
8. Mock 功能有清楚標示，不宣稱已寄信、已持久化或已呼叫 AI。
9. `npm run typecheck`、`npm test`、`npm run build` 在相依環境中通過。

測試執行狀態以 [TEST_PLAN](./TEST_PLAN.md) 為準，不因列入驗收條件就視為已測試。

## 12. 現有限制

- 所有產品資料與流程位於 `DemoApp.tsx`，無 API 或持久化。
- Demo 角色切換不是安全權限；`chatgpt-auth.ts` 未接到產品頁。
- Email、Interview Token、驗證、AI、自動儲存與倒數皆為 Mock 或靜態 UI。
- 技術審核與 HR 摘要沒有完整跨角色資料同步。
- 只有首頁 SSR smoke test；互動、權限、RWD 與無障礙尚未自動化。
- 無正式資料保留、隱私、監控、告警或災難復原方案。
